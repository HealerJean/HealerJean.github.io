## 二、 各工具深度剖析与适用场景

## 1、`OpenPDF` —— 规避 iText 产权风险的首选

- **技术背景**：由于 iText 从第 5 版开始全面转向 AGPL 严厉开源协议（企业闭源商用必须买授权，否则属于侵权），社区基于免费时期的 iText 4 独立 fork 出了 OpenPDF。
- **性能表现**：继承了 iText 优秀的底层架构，同样支持大表格流式写入。2 万行表格在合理优化下也可以在 1.5 秒左右完成。
- **适用场景**：**预算有限、需要免费商用**，同时对性能要求极高的企业核心业务（如高并发电子凭证、批量对账单）。



## 2、`Apache PDFBox` —— 官方的“画笔”

- **技术背景**：Apache 官方出品。它非常底层，它没有 `Paragraph（段落）`、`Table（表格）` 的概念。你要写一句话，得先定位 `(x, y)` 坐标，然后调用 `showText()`。

- **性能表现**：如果自己封装好表格组件，性能其实非常高。但由于缺乏高层封装，开发动态表格极其痛苦。

- **适用场景**：PDF 文本提取、PDF 签名加盖章、转图片，或者极简单的单页证明生成。

  

## 3、`OpenHtmlToPdf` —— 告别手写坐标的现代方案

- **技术背景**：由于目前前端写 HTML/CSS 最快，这个工具可以让你用现代网页思维设计 PDF。它内置了更现代的 PDFBox 作为底层渲染。
- **性能表现**：**不适合 2 万行级别的大动态表格**。因为它必须在内存中构建完整的 DOM 树，2 万行数据会导致 JVM 堆内存瞬间飙升，引发频繁的 Full GC，耗时通常会放大数倍甚至 OOM。
- **适用场景**：精美的图文报告、宣传单页、行数较少（几百行以内）且样式极其复杂的合同、简历。



## 4、`JasperReports `—— 传统政企报表之王

- **技术背景**：通过专用的桌面设计器（Jaspersoft Studio）像画工业图纸一样拖拽设计模板（`.jrxml` 文件），然后 Java 加载数据源（支持各种数据库或 Java Bean 集合）直接灌入。
- **性能表现**：它内部优化了大数据量的虚拟化（Virtualization）机制，即使是 2 万行甚至 10 万行数据，它也可以一边分页一边释放内存，性能和稳定性非常好。
- **适用场景**：经典的政企 ERP 系统、财务系统的后台大报表导出。



# 三、 终极选型决策树

1. **如果你追求“纯运行速度” + 允许纯代码硬写（或商业预算充足）：**
   👉 选 **iText 7**（商业授权）或 **OpenPDF**（免费商用）。
2. **如果你追求“开发速度最快” + 数据量很小（100行以内）：**
   👉 选 **OpenHtmlToPdf**（HTML转PDF）。
3. **如果是“2万行大表格” + “要可视化改模板” + “免费商用”：**
   👉 别犹豫，唯一解是 **JasperReports**。
